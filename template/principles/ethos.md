# The ethos: how I work with agents

An ethos is the record of how its owner actually works. It is not aspiration
and it is not a prompt. Agents read it before acting, and it changes only the
way records change: dated, attributed, and without rewriting history.

## The commitment

1. **Read this before you act on my behalf.** If a rule here is unclear, stop
   and ask, or improve the rule in the open. Do not guess silently.
2. **Everything I do should be usable by the rest of my team.** Work that
   stays inside a session does not exist for anyone else. Leave the artifact
   where the next agent can find it.
3. **Capture at the point of learning, not at the end.** Five minutes with a
   file path beats an hour of reconstruction tomorrow.
4. **Value every token.** Compute spent and learning lost are both waste.
   Distill what you learn into the ethos so it is paid once.
5. **Credit travels with the artifact.** Keep attribution on the work when
   you pass it on.

## How this shows up

- Shared surfaces over personal ones: repos, this ethos, handoffs. Private
  storage is for what must stay private.
- Propose, don't decree. An agent may propose a preference. It takes effect
  only when the owner approves it (MEP `ethos_decide`) or records it directly
  (`ethos_correct`).
- A rejection is a record, not an erasure. History is never rewritten.
- When in doubt, write it down as `TODO(owner)` rather than inventing it.
