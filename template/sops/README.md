# SOPs

Step-by-step practice for recurring work. An SOP here wins over a habit
re-derived each session.

Suggested starting points, in the order most owners need them:

- `github.md`: how repositories, PRs and merges work for you.
- `shipping.md`: how work gets from done to released.
- `review.md`: how review happens, and who decides.
- `capture.md`: the end-of-session questions (or run the `reflect` prompt
  from the MEP server).

Write one when the same procedure happens twice. Keep each SOP dated, kept
short enough to actually follow, and delete the ones that no longer apply
(leave a tombstone in the changelog, never a silent deletion).
